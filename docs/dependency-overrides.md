# pnpm.overrides provenance

The root `package.json` pins transitive dependency versions via `pnpm.overrides`
because upstream parents (firebase-admin, firebase-tools, @google-cloud/storage,
gaxios, google-auth-library, and various dev/build tooling) had not yet picked up
patched versions of these packages when a Dependabot advisory was opened against
them. JSON does not support comments, so provenance is tracked here instead.

When bumping an override, verify whether the parent package now ships a version
that includes the fix; if so, remove the override entirely rather than bumping it.

## Direct dependency bumps (not overrides)

directly, so they were fixed by raising the declared range rather than by adding
an override:

| Package             | Where               | Change            | Advisory                                       |

## Known-open, assessed as not applicable

- **Alert #86 — react-router "RSC Mode CSRF Bypass" (high).** Patched only in
  react-router 8.3.0, and `react-router-dom` has no 8.x line (the package was
  consolidated into `react-router` at v8), so it cannot be closed by upgrading
  while `apps/web` is on the 7.x line. The advisory states it "only affects your
  application if you are using the unstable RSC APIs"; `apps/web` is a plain SPA
  that imports exclusively from `react-router-dom` and uses no `unstable_*` or
  RSC entry points. Revisit if the app ever migrates to react-router 8 or adopts
  RSC. Safe to dismiss in Dependabot as "not affected" — that dismissal is the
  repo owner's call, so it has been left open rather than dismissed unilaterally.
